FIVE-MINUTE CODE TOUR

UAT Scenario Generator

A plain-language change travels from the page to one server route, through Gemini and Zod validation, and back as readable scenario cards.

Map snapshot: commit de62541. It is intentionally a lightweight guide and may drift after future code changes.

The route in one picture

1. Page
Enter a change and submit
→
2. API route
Validate, call Gemini, validate again
→
3. Results
Render the latest scenario cards

Tour stops

1. Start at the user action

app/page.tsx · handleSubmit

This function rejects empty input, switches on the loading state, sends {"change": "..."} to the route, and stores the latest returned scenarios in browser memory.

2. Follow the server boundary

app/api/generate/route.ts · POST

The route validates the request with the shared schema, calls the model helper, validates the complete response, and returns either {"scenarios": [...]} or a simple error.

3. See the model contract and output

lib/gemini.ts · generateScenarios; then app/page.tsx · scenario list

Gemini receives the structured-output schema and the instruction not to invent unsupported product details. The page renders required fields, optional preconditions, and one visual list number per step.

To change this, start here

Change the page copy, card layout, or step display: start in app/page.tsx and app/globals.css.
Change required scenario fields or count: update lib/schemas.ts, then keep the Gemini schema in lib/gemini.ts aligned.
Change generation guidance or model selection: update lib/gemini.ts or the local GEMINI_MODEL value in .env.local.
Change the API error contract: start in app/api/generate/route.ts and update the page's error handling with it.

Run it again

npm install
cp .env.example .env.local
# add GEMINI_API_KEY to .env.local
npm run dev

Open the forwarded Codespaces port, normally http://localhost:3000. The map works offline and has no scripts, framework, CDN, analytics, or secrets.

A few useful details

Where validation lives

Request and response validation are defined in lib/schemas.ts. The route uses safeParse so malformed model output never becomes partial UI.

What is deliberately not here

There is no database, authentication, saved history, collaboration, platform integration, or deployment configuration. The project is sized for a local proof of concept.
